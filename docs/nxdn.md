# NXDN48 receive (`CONFIG_NXDN`, ours; receive only)

Status 2026-11-17: protocol core and host tests done; board glue written and syntax-checked against the patched
Classic tree (csky-elf-gcc `-fsyntax-only`), **not built into Plus, not run on a radio**. No transmit.

NXDN48 (6.25 kHz, 2400 symbols/s 4FSK, +-1050 / +-350 Hz, AMBE+2 voice) is what amateur NXDN uses. The HR_C7000's
4FSK stream runs only at 4800 symbols/s, so (as DM32-nxdn-p25 found) the radio stays in **FM mode** and a software
demodulator runs on the HR_C7000's 8 kHz FM RX RAM copy of the discriminator audio. The 72-bit NXDN voice field is
bit for bit the DMR AMBE+2 air frame, so it goes straight to RadioFoundry's `ambeVoiceSink()` like YSF DN.

```
FD6818 discriminator (0x2B = 0x0700, flat) -> HR_C7000 FM RX RAM, 8 kHz, 256-sample halves (SYS_INTERP b14)
  -> fm_rx_audio.c heap ring (APRS's path: board.afsk rx_start / rx_read)
  -> src/nxdn: demodulator -> FSW sync (both polarities) -> LICH -> SACCH / FACCH1 -> VCALL caller, RAN filter
  -> 72-bit voice fields -> paced 20 ms -> ambeVoiceSink() (stock AMBE+2 vocoder) -> PCM speaker path
```

dPMR (`CONFIG_DPMR`, docs/dpmr.md, 2026-11-18) runs on this path too: the same demodulator, flat audio, pacing and
receiver object (`radio_nxdn.c` holds both receivers in a union, one listening at a time); a change to
`nxdn_demod.c` or `radio_nxdn.c` must keep `tests/plus/test_dpmr.c` passing as well.

`sizeof`: `nxdn_demod_t` 216, `nxdn_rx_t` 356 (Viterbi survivors 192), `nxdn_receiver_t` 576 on the CK803S.
Stack below `nxdn_receiver_audio` about 450 B (`-fstack-usage`, Viterbi 200) plus the voice callback; it runs in the
radio task. If the heap (~3.8 KB spare by estimate, docs/plus.md) turns out too short, build with
`-DRADIO_NXDN_HEAP=0` (+830 B static) or check `tasks.heap_min_free` first. CPU: two 31-tap filters a symbol
(~150 k MAC/s) plus a 16-state Viterbi per frame: about 1-2 % of the 168 MHz CPU (estimate, not measured).

## Host tests

```sh
# WSL, any scratch dir; zero warnings, ASan + UBSan
clang -std=c11 -O1 -g -Wall -Wextra -Werror -fsanitize=address,undefined -fno-sanitize-recover=undefined -Isrc \
  tests/plus/test_nxdn.c src/nxdn/nxdn.c src/nxdn/nxdn_demod.c src/nxdn/nxdn_rx.c -lm -o /tmp/test_nxdn && /tmp/test_nxdn
NXDN_REF_RF=build/radiofoundry-p25 NXDN_REF_OUT=/tmp/nxdn-ref bash tools/test_nxdn_ref.sh   # needs ../research/ref/MMDVMHost
```

`test_nxdn` (clang and gcc, all passed): PN9 scrambler regenerated; LICH parity for all 256 bytes; Golay 0-3 errors
corrected, 4 always detected; AMBE field 49 bits back through 3 + 3 errors; SACCH / FACCH1 with errors at distinct
places (SACCH 0-2 errors 1500/1500 each, 3: 1453; FACCH1 0-1: 1000/1000, 2: 989, 3: 944; no wrong decode with a good
CRC); whole transmissions as 8 kHz samples (RRC 0.2 x sin(x)/x pulse): clean call (48/48 fields bit exact, caller
1234 > 100, release), noise + 150 Hz carrier error + 50 ppm + odd timing phase + FACCH1 steal (98/98), 300 ppm
clock error (BER < 1 %), 300 Hz rms noise (BER 1.1 %, caller right), inverted discriminator, late entry from the
SACCH superframe, foreign RAN, other group / group ALL, encrypted (reported, muted), individual calls, two callers
back to back without a release, 20 s of noise at three levels (no call, no voice), a call after 3 s of noise.

`test_nxdn_ref` (all passed): scrambler equals MMDVMHost's table; C1 whitening equals its PRNG_TABLE for all 4096
values; every RDCH LICH MMDVMHost builds decodes; SACCH / FACCH1 built by `CNXDNSACCH` / `CNXDNFACCH1` decode with
0-4 / 0-6 errors at least as often as MMDVMHost's own decoder (e.g. SACCH 4 errors 1212 vs 958 of 1400, ours
treats punctured bits as erasures); layer 3 fields equal `CNXDNLayer3`'s; `CNXDNAudio::encode` fields give our 49 bits
back and equal `ambeFecEncode` of them (**the NXDN field is the DMR air frame**), and with errors ours equals
`ambeFecDecode` bit for bit and in the error count (6000 cases); whole calls built with MMDVMHost's classes (header +
8 voice frames + release, and late entry) give caller 12345 > TG 101, RAN 12 and every voice field. MMDVMHost's own
`CNXDNFACCH1::encode` reads one entry past `PUNCTURE_LIST` (UBSan): the script builds the reference without
sanitizers.

## Wiring into Plus (for the main session)

Switch `CONFIG_NXDN` (needs `DMR=y`, `APRS_RX=y`, `P25_CHANNELS=y` for the channel mode plumbing). Channel mode
`RADIO_MODE_NXDN = 4`, codeplug marker **`CH_MODE 0xA7`**, RAN (0 = any, 1-63) in `CH_RX_GROUP` mapped to `ch->p25_tg`
(as YSF's DG-ID), always `rx_only`, `bw` 12.5 kHz. Unlike YSF, NXDN is **not** a native-modem channel:
`codeplug_mode_p25()` stays false for it (the native worker must not take it); `codeplug_mode_nxdn()` tells it.
`tune()` already tunes every non-DMR mode as FM; `outputs()` already keeps the analog speaker shut when the channel's
mode is not `RADIO_MODE_FM`; `aprs_poll()` already doesn't listen on it (same reason), so the FM ring is free.

`prepare_nxdn(transform, install)` in `tools/plus_features.py`, called from `prepare()` after `prepare_ysf`:

1. Install: `core/nxdn/{nxdn.c,nxdn.h,nxdn_demod.c,nxdn_demod.h,nxdn_demod_tables.inc,nxdn_rx.c,nxdn_rx.h}` from
   `src/nxdn/`; `core/radio/radio_nxdn.{c,h}` from `integration/radiofoundry/nxdn/`; `boards/dm32/dm32_nxdn.inc`.
   (`radio_nxdn.c` includes `"radio/radio_nxdn.h"` and `"nxdn/nxdn_rx.h"`: core is an include root, as for ysf.)
2. `config/features.mk`: `CONFIG_NXDN ?= n`, `FEATURES += NXDN`, and an `$(error NXDN needs DMR=y, APRS_RX=y and
   P25_CHANNELS=y)` guard. `core/config.h`: `#ifndef CONFIG_NXDN / #define CONFIG_NXDN 0`.
   `Makefile`: `ifeq ($(CONFIG_NXDN),y) CORE_DIRS += core/nxdn endif` (core/radio is already built).
3. `boards/dm32/radio_dm32.c`: after `#include "dm32_native.inc"` add `#include "dm32_nxdn.inc"` (the file has its own
   `#if CONFIG_NXDN`).
4. `core/codeplug/codeplug.h`: `RADIO_MODE_NXDN = 4` beside `RADIO_MODE_YSF = 3`; `codeplug_mode_nxdn()` like
   `codeplug_mode_ysf()`; validity: `bw == RADIO_BW_12K5 && rx_only && p25_tg <= 63`.
   `codeplug.c`: accept `0xA7` on load (`mode = RADIO_MODE_NXDN`, `p25_tg = r[CH_RX_GROUP] & 0x3F`, `p25_nac = 0`,
   `rx_only = true`, `dmo/roam/vox = false`); store `0xA7` and the RAN byte, mirroring the YSF lines.
5. `core/radio/radio_sm.c`:
   - include `radio/radio_nxdn.h` under `#if CONFIG_NXDN`;
   - in `radio_sm_poll()` right after `aprs_poll(sm, now_ms);`:
     `radio_nxdn_poll(codeplug_mode_nxdn(sm->view.ch.mode) && sm->view.state != RS_TX && sm->board_mode ==
     RADIO_MODE_FM && !scan_on(&sm->scan) && !spectrum_on() && !p25s_on() && !sm->view.bcast, sm->view.ch.rx_hz,
     (uint8_t)sm->view.ch.p25_tg, now_ms);` (drop the terms whose CONFIG is off);
   - `outputs()`: `if (codeplug_mode_nxdn(sm->view.ch.mode)) green = radio_nxdn_heard(now)` (pass `now_ms` or use
     `hal_millis()`);
   - TX check: `if (codeplug_mode_nxdn(ch->mode)) return TXDENY_MODE;` before the FM/DMR test (rx_only already
     denies; this is the belt);
   - scan and dual watch: leave NXDN channels out (`&& !codeplug_mode_nxdn(ch.mode)` in the scan member test, and
     refuse it as the dual-watch partner) until a later pass;
   - battery save: no `rx_sleep` on an NXDN channel (the demodulator needs the audio all the time): add it to
     whatever condition keeps save off for P25.
6. UI (`ui_menus.c`, `ui_screens.c`, `ui_dual.c`, `debuglink_view.c`), mirroring YSF: Mode cycles FM -> DMR -> P25 ->
   YSF -> NXDN -> FM; label "NXDN"; the `CE_P25_TG` row labelled "RAN" (0-63) and NAC / ID rows hidden; Home's bottom
   line from `radio_nxdn_caller()`: `"NXDN 1234 > TG 101"` (group), `"NXDN 1234 > 5678"` (individual), `"NXDN ENC
   1234"` when encrypted (not played), `"NXDN call"` before the caller is known; debug view mode string `"nxdn"`.
7. `tools/test_classic.py`, beside the YSF lines:
   `run(['clang',*flags,'-I'+str(ROOT/'src'),ROOT/'tests/plus/test_nxdn.c',ROOT/'src/nxdn/nxdn.c',`
   `ROOT/'src/nxdn/nxdn_demod.c',ROOT/'src/nxdn/nxdn_rx.c','-lm','-o',OUT/'test_nxdn'],cwd=ROOT)` then
   `run([OUT/'test_nxdn'],cwd=ROOT)` (the test needs `-lm`; it runs in ~0.2 s). A channel-store test like
   `test_ysf_channel.c` for `0xA7` belongs with step 4.
8. Build: add `NXDN` to the Plus preset only after `--plus --stack-check --verify-rebuild` shows the RAM and the
   radio task's stack still fit (radio task + ~450 B below `radio_nxdn_poll`).

## What the radio must confirm (all of it unverified on our tree)

1. RX RAM audio arrives in FM on an NXDN channel with `aprs_listen_route` on and the squelch shut (APRS proves the
   path on FM channels; the NXDN channel's `outputs()` state is new).
2. The flat recipe on this unit: 0x2B = 0x0700 bypasses de-emphasis / HPF / LPF in RX (measure a tone sweep in RX RAM
   via the debug link's memory read); if a droop remains, set `nxdn_receiver_init(..., hpf_hz, deemph_us)`.
3. Level: an NXDN48 signal's RX RAM peak (outer symbols ~1.05 kHz) well below full scale; noise may clip (harmless).
4. Polarity: either works (both are hunted); `rx.inverted` tells which, worth recording.
5. `hrc7000_fm_rx()` resetting FM_BANDWIDTH b6 on retune (handled by re-applying), and nothing else in `rx()` undoing
   0x2B.
6. The stock AMBE+2 vocoder and the PCM speaker path in **FM board mode** (`ambeVoiceSink` was only used in DMR mode
   so far: DMR calls and YSF DN). Beeps use the same PCM path in FM, so it is likely, not proven.
7. Pacing: no ambeVoice underruns / overflows (`ambe_voice_stats_t` over the debug link) with the radio task's real
   poll period.
8. Heap: `tasks.heap_min_free` with an NXDN channel listening.
9. Interoperability: an NXDN48 transmitter is needed (an Icom / Kenwood radio, an MMDVM hotspot in NXDN mode, or an
   SDR playing a capture). The owner has none yet (docs/plus.md); host tests only prove agreement with MMDVMHost.

Open items after that: NXDN in scan / dual watch, a group filter in the channel (the core has one: `nxdn_rx_cfg_t
group`, `unit`), and TX (behind `--tx-bench` and owner approval; the source project's TX is not interoperable).
